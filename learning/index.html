LAYER 01

What is WebAssembly?

A portable binary instruction format — a compile target that runs at near-native speed inside a sandbox. You compile Rust, Python, TypeScript, Go… down to WASM, and any runtime can execute it. Think "assembly for a virtual CPU that doesn't physically exist."

Portable

One binary, runs anywhere

Any OS/CPU with a runtime. Like a container — but the unit is a function-level sandbox, not a whole Linux userland.

Sandboxed

Can do nothing by default

No files, no network, no clock — unless the host explicitly grants the capability. Deny-by-default isolation.

Fast & tiny

Microsecond cold start

No OS boot like a VM or container. Modules can be kilobytes.

Say this on stage → A container ships an entire OS image and isolates via the kernel (namespaces/cgroups). WASM isolates via the language sandbox and ships just the code: smaller, faster cold-start, finer-grained.
LAYER 02

The gap WASM had — and the Component Model

Plain WASM modules only speak in numbers — i32, i64, f32, f64. No strings, no structs, no lists at the boundary. So two modules from two languages couldn't really talk without hand-written byte-marshalling glue. The Component Model fixes this with typed interfaces.

WIT — WASM Interface Types

The IDL (like protobuf / OpenAPI) where you declare interfaces in rich types — strings, records, lists, results. Each component says "I import these, I export these"; the runtime does the marshalling.

A component = module + WIT

The composable unit. wasmcp compose snaps components together at their WIT seams into one artifact — no network calls between them, no per-language runtime running as a side process.

Stage analogy → WIT is the shape of the plug; the Component Model is the standard socket. Differently-colored language blocks click together because they agree on the plug shape.

LAYER 03

What is MCP?

Model Context Protocol — an open standard for exposing callable tools to LLM clients. A server advertises tools (list_tools) with typed input schemas; clients call them (call_tool). "USB-C for LLM tools" — one protocol, any client, any tool.

Every polyhue component is an MCP server

  • color-rs → tool get_color_rs
  • color-py → blue palette
  • color-ts → gold palette
  • policy-gate → tool peek_attendees

The thesis

The composed binary is one MCP server whose tools happen to be implemented in three different languages — plus a real policy gate. One artifact. Zero network glue between the tools.

LAYER 05

What happens when a phone loads the page

phone loads page → POST /color {seed} → serve.py hashes seed → picks a language → calls that language's get_color_* MCP tool → returns HSL → phone paints itself
  • The color is deterministic from the seed — same seed, same hue. So every phone reproducibly sorts into one of three language groups.
  • Each language owns a hue band — Rust hue 10–30 (red-orange), Python blue, TS gold.
  • serve.py is a dev proxy: routes /color, forwards /mcp to Spin, fans out a Server-Sent-Events stream on /events.
LAYER 06 · the big beat

The policy gate — two decoupled halves

Pick a tool to "call." A real Regorus (Rego / OPA engine, compiled Rust→WASM) evaluates the policy in-process, inside the composed binary. Then watch what the proxy chooses to do with a denial.

default allow := false allow if { input.action != "peek_attendees" }
— pick a tool —
Regorus evaluates data.authz.allow against the input.
Be precise on stage — this is your credibility:
  • The gate is real. A genuine OPA-style policy engine runs in-process — no sidecar, no external PDP. The denial is a first-class signal.
  • The red flash is proxy theater, not policy. Regorus denies one caller. serve.py /trigger-denial sees isError:true and chooses to broadcast a flash SSE event to every phone.
  • If asked "is that real access control?" — No. No identity/role/user; the policy is a demo prop. Claim the mechanism, not the policy's sophistication.

The 60-second version

WASM = portable sandboxed binary. Plain WASM only speaks numbers, so languages couldn't compose. The Component Model + WIT give typed interfaces so they can — snapping into one binary. MCP is the standard for exposing tools to LLM clients. polyhue takes three color-tool components in three languages + a real in-process Rego policy gate, composes them with wasmcp into one .wasm MCP server. Phones hit it, sort into three color groups by language, and a real policy denial triggers a room-wide red flash. One binary, three languages, zero glue.
